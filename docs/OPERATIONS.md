# Operating with stack-kit

Generated by `stack-kit help --markdown` from the verb registry (lib/cli/verbs/); regenerate, never edit.
Every verb runs the same in a terminal and in CI. A verb that changes a server prints its plan -- the
exact remote paths and commands -- before it acts; `--plan` stops there and writes nothing.

## Exit codes

| code | meaning |
|---|---|
| 0 | done (or, with --plan, planned) |
| 1 | failed: a step or a declaration was wrong; the message names it |
| 2 | not run: a usage error, or nothing selectable (no target, a pending one, a non-workspace environment) |
| 3 | refused: ownership -- the directory carries another project's marker, or none |
| 4 | refused by the preflight: runtime, ports or disk |
| 5 | refused: provenance -- a dirty checkout or an archive without release.json where a clean commit is required |
| 6 | unhealthy: a service did not become healthy (a release in a rolling-back environment was rolled back) |
| 130 | interrupted |

## Deploy and operate

### `deploy`

build -> package -> ship -> up -> health, for a module or all, to one environment.

```
stack-kit deploy <module|all> --env <id> [--target <t>] [--plan] [--yes] [--artifact <archive>]
```

| option | |
|---|---|
| `--plan` | print the plan -- remote paths and commands -- and stop; nothing is written |
| `--yes` | answer the confirmation (CI); without a terminal a confirmation is otherwise refused |
| `--artifact <archive>` | deploy this archive (CI: the one packaged earlier) |
| `--target <name>` | the declared deploy target (default: the environment's) |
| `--env <id>` | the environment (catalogs.environments; --dev / --prod are short for it) |

An environment that requires a clean checkout refuses a dirty one; one that asks first (`confirm`) asks on a terminal and refuses without one unless --yes. A commit already packaged is not rebuilt. A failed health rolls back where the environment declares it.

Exit codes: 0, 1, 2, 3, 4, 5, 6.

```
stack-kit deploy api --env dev --plan
stack-kit deploy all --env prod --yes
```

### `infra`

the infra stack: on this machine, or on the target in its layout's infra place.

```
stack-kit infra local up|down|status [--prod]
stack-kit infra remote sync|up|down|status|purge --env <id> [--target <t>] [--plan] [--yes]
stack-kit infra tunnel --env <id> [--target <t>]
```

| option | |
|---|---|
| `--plan` | print the plan and stop; nothing is written |
| `--yes` | answer the confirmation (CI) |
| `--target <name>` | the declared deploy target (default: the environment's) |
| `--env <id>` | the environment (catalogs.environments; --dev / --prod are short for it) |

Exit codes: 0, 1, 2, 3, 4.

```
stack-kit infra remote up --env dev --plan
stack-kit infra tunnel --env dev
```

### `layout`

move this project's services out of a tree laid out before the layout.

```
stack-kit layout migrate --target <t> --env <id> [--approve] [--yes]
```

| option | |
|---|---|
| `--plan` | print the plan -- remote paths and commands -- and stop; nothing is written |
| `--yes` | answer the confirmation (CI); without a terminal a confirmation is otherwise refused |
| `--approve` | apply the planned moves (never automatic) |
| `--target <name>` | the declared deploy target (default: the environment's) |
| `--env <id>` | the environment (catalogs.environments; --dev / --prod are short for it) |

Only what the target declares as this project's (`legacyLayout`) moves, never a folder a listing finds; a direct child of the shared root is never moved.

Exit codes: 0, 1, 2, 3.

### `ops`

operate a deployed environment, per service, module or tier (or all).

```
stack-kit ops status|logs|start|stop|restart|rebuild [module|service|tier ...] --env <id>
stack-kit ops rm <module|service|tier ...> --env <id> [--yes]
stack-kit ops nuke --env <id> [--yes]
```

| option | |
|---|---|
| `--plan` | print the plan -- remote paths and commands -- and stop; nothing is written |
| `--yes` | answer the confirmation (CI); without a terminal a confirmation is otherwise refused |
| `--follow` | logs: keep following |
| `--tail <n>` | logs: lines (default 200) |
| `--target <name>` | the declared deploy target (default: the environment's) |
| `--env <id>` | the environment (catalogs.environments; --dev / --prod are short for it) |

rm and nuke ask first and act only inside the project's own environment directory, which must carry this project's ownership marker; never at the target's root.

Exit codes: 0, 1, 2, 3, 6.

```
stack-kit ops status --env prod
stack-kit ops logs api --env dev --follow
```

### `package`

build once: the driver's package step, then one archive of this commit with its provenance.

```
stack-kit package <module|all> [...]
```

| option | |
|---|---|
| `--target <name>` | the declared deploy target (default: the environment's) |
| `--env <id>` | the environment (catalogs.environments; --dev / --prod are short for it) |

The archive is `.stack-kit/artifacts/<module>-<commit>[-dirty].tgz` with its sha256 beside it; `release.json` inside it carries the commit, `git describe --tags --always --dirty` and the services.

Exit codes: 0, 1, 2.

```
stack-kit package api
```

### `release`

a unit's releases, and moving `current` back.

```
stack-kit release list [module ...] --env <id>
stack-kit release rollback [module ...] [--to <id>] --env <id>
```

| option | |
|---|---|
| `--plan` | print the plan -- remote paths and commands -- and stop; nothing is written |
| `--yes` | answer the confirmation (CI); without a terminal a confirmation is otherwise refused |
| `--to <id>` | the release to roll back to (default: the one before current) |
| `--target <name>` | the declared deploy target (default: the environment's) |
| `--env <id>` | the environment (catalogs.environments; --dev / --prod are short for it) |

Exit codes: 0, 1, 2, 3, 6.

```
stack-kit release list --env prod
stack-kit release rollback api --env prod --yes
```

### `targets`

the declared deploy targets: list, plan the tree, create it, verify it, check health.

```
stack-kit targets [--plan] [--env <id>]
stack-kit targets --init --target <t> --env <id> [--plan]
stack-kit targets --verify --target <t> --env <id>
stack-kit targets --health --target <t> --env <id>
```

| option | |
|---|---|
| `--plan` | print the plan -- remote paths and commands -- and stop; nothing is written |
| `--yes` | answer the confirmation (CI); without a terminal a confirmation is otherwise refused |
| `--init` | create the project's tree with its ownership marker (idempotent) |
| `--verify` | read-only: marker, tree, current, prune limit, runtime, ports, disk |
| `--health` | the target's declared health URLs answer below 400 |
| `--attempts <n>` | health: attempts per URL (default 12) |
| `--pause <s>` | health: seconds between attempts (default 5) |
| `--target <name>` | the declared deploy target (default: the environment's) |
| `--env <id>` | the environment (catalogs.environments; --dev / --prod are short for it) |

--init refuses a non-empty directory without this project's marker; --verify reads the declared state (places, marker, compose file, env and runtime config digests, each service's running release, runtime, ports, disk) against the host, read-only, and exits 1 on drift, 2 when nothing could be verified; a drift is undone by the verb that owns it (deploy, release rollback).

Exit codes: 0, 1, 2, 3, 4.

```
stack-kit targets --plan
stack-kit targets --init --target linux --env dev
```

## Remote dev

### `dev`

remote dev: the module's source synced into its workspace and run by its driver's dev container.

```
stack-kit dev up <module|all> [--target <t>] [--plan]
stack-kit dev up <module|all> --mode hybrid|local|docker   (this machine)
stack-kit dev sync <module> [--full]
stack-kit dev watch <module|all>
stack-kit dev down <module|all>
stack-kit dev logs <module> [--follow]
stack-kit dev status
stack-kit dev shell <module>
stack-kit dev tunnel <module>
```

| option | |
|---|---|
| `--plan` | print the plan -- remote paths and commands -- and stop; nothing is written |
| `--yes` | answer the confirmation (CI); without a terminal a confirmation is otherwise refused |
| `--mode <mode>` | up: a local mode instead (hybrid, local, docker) |
| `--full` | sync: compare every file again (after a lost connection) |
| `--no-infra` | up --mode hybrid: the infra stack is running already |
| `--no-tunnel` | up --mode hybrid: open no tunnel |
| `--follow` | logs: keep following |
| `--target <name>` | the declared deploy target (default: the environment's) |
| `--env <id>` | the environment (catalogs.environments; --dev / --prod are short for it) |

The workspace is the layout's ({root}/{project}/dev/{tier}/{service}/workspace). A sync uses rsync when both ends have it, else the built-in index + tar stream over ssh; env files, keys and credential files are never sent. `watch` polls (no extra dependency), debounces, syncs, and reacts as the driver declares: hot-reload, restart, or rebuild; a lost connection is retried and followed by a full sync.

Exit codes: 0, 1, 2, 3, 4, 6.

```
stack-kit dev up api --target linux --plan
stack-kit dev watch api
stack-kit dev tunnel api
```

## The project

### `<step>`

a lifecycle step (catalogs.lifecycle: lint, build, test, ...) for every module, fail-fast.

```
stack-kit <step> [module ...]
```

Exit codes: 0, 1, 2.

```
stack-kit build
stack-kit test api
```

### `config`

the configuration catalogue's env-value policy against this machine's env files (names, never values).

```
stack-kit config check [module ...] [--env <id>]
```

The same policy every release runs before it writes an env file: required (or required only in an environment), no placeholder, a minimum length, a format (positive-int, url, https-url without localhost), values an environment forbids (a wildcard CORS origin in prod), keys another requires.

Exit codes: 0, 1.

```
stack-kit config check --env prod
```

### `help`

the verbs, or one verb's help, or the generated operator documentation.

```
stack-kit help [verb]
stack-kit help --markdown
```

| option | |
|---|---|
| `--markdown` | the operator documentation (OPERATIONS.md) |

Exit codes: 0.

### `hybrid`

run a module on this machine with its environment's env files.

```
stack-kit hybrid boot <module> [--env dev]
```

| option | |
|---|---|
| `--env <id>` | the environment whose env files the run reads (default dev) |

Exit codes: 0, 1, 2.

```
stack-kit hybrid boot api
```

### `init`

bootstrap a host, or draft its manifest from the tree.

```
stack-kit init
stack-kit init --plan
stack-kit init --approve <who>
```

`--plan` drafts the manifest from the evidence each driver declares (declared fields always win); `--approve <who>` writes the draft.

Exit codes: 0, 1, 2.

```
stack-kit init --plan
```

### `migrate`

carry a host's older declarations into their current homes.

```
stack-kit migrate [--apply]
```

Without --apply it lists what would change. It is the only reader of the legacy homes (deploy.env, .env.deploy, DEPLOY_*/COMPOSE_* keys): it moves their values into the manifest and the targets file, and removes them.

Exit codes: 0, 1.

### `mod`

a command a module's driver declares, or a rung of its delivery ladder.

```
stack-kit mod <module> <command> [operands]
stack-kit mod <module> deliver <rung> [--env <id>] [--plan]
stack-kit <alias> <command> [operands]
```

A rung `via` a kit verb runs that verb (release -> deploy, remote-dev -> dev up, hybrid -> hybrid boot).

Exit codes: 0, 1, 2.

```
stack-kit mod api build
stack-kit mod api deliver release --env prod --plan
```

### `stack`

the local development stack, run by this machine's declared compose invocation.

```
stack-kit stack <up|down|ps|logs> ... [--env dev|prod]
```

Exit codes: 0, 1, 2.

### `validate`

validate the manifest, its declarations and the deploy targets.

```
stack-kit validate [--stages]
```

Exit codes: 0, 1.

## Generated files

### `ci-gen`

generate the CI/CD workflow from the manifest and the targets.

```
stack-kit ci-gen [--force|--check]
```

CD calls this same CLI (`deploy --yes`), never deploy logic of its own: a manual dispatch with an environment choice, and each environment gated by its GitHub Environment (give production required reviewers in the repository settings).

Exit codes: 0, 1, 2.

### `compose-gen`

generate the local development compose files.

```
stack-kit compose-gen
```

Exit codes: 0, 1, 2.

### `config-gen`

generate module config from the manifest.

```
stack-kit config-gen [--all|--check|--dry-run] [module]
```

Exit codes: 0, 1, 2.

### `nginx-gen`

render the UI module's nginx config.

```
stack-kit nginx-gen
```

Exit codes: 0, 1, 2.

### `vscode-gen`

generate .vscode launch and tasks from the manifest.

```
stack-kit vscode-gen [--force]
```

Exit codes: 0, 1, 2.
